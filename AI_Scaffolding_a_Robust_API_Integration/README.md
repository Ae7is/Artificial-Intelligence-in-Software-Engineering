# AI: Scaffolding a Robust API Integration

## Objective

Use a Contextual Prompting technique to have an AI refactor the
`analyze_sentiment` function of `sentiment_analyzer.py` so that it:

- reads an API key securely from the environment variable
  `TEXT_PROCESSING_API_KEY` and sends it as `Authorization: Bearer <key>`
- handles `requests.exceptions.Timeout` and
  `requests.exceptions.ConnectionError` explicitly, each with a distinct
  message on `sys.stderr`

## Contextual Prompt

The prompt had three parts: the context, the task and the refinement. The
context was the full text of `sentiment_analyzer_initial.py`, pasted
into the prompt (not repeated here).

**Task:**

> Refactor only the analyze_sentiment function so that it securely reads an
> API key from the environment variable TEXT_PROCESSING_API_KEY (using the os
> module, never hardcoding the key) and sends it in the request headers in the
> standard format Authorization: Bearer <key>. If the variable is not set,
> print a clear error to sys.stderr and return None without sending the
> request.

**Refinement:**

> Improve the error handling by explicitly adding except blocks for
> requests.exceptions.Timeout and requests.exceptions.ConnectionError, in
> addition to the existing HTTPError, RequestException and (KeyError,
> ValueError) blocks. Each block must print a distinct, informative message to
> sys.stderr and return None. Pass a timeout argument to requests.post so the
> Timeout exception can actually occur, and order the except blocks from most
> specific to most general.

**Constraints:**

> Keep the function name, the return values (positive, negative, neutral, or
> None on error) and the rest of the script unchanged. Return the complete
> updated file, followed by a short list of what you changed and why.

AI tool used: (ChatGPT -6, 21 October 2026) .

## What Changed

| Area | Initial code | Refactored code |
|---|---|---|
| Authentication | None | Key read with `os.environ.get("TEXT_PROCESSING_API_KEY")` and sent as `Authorization: Bearer <key>` |
| Missing key | Not handled | Error printed to `sys.stderr`, returns `None`, no request is sent |
| Timeout | No timeout set | `timeout=10` on `requests.post` |
| Exceptions | `HTTPError`, `RequestException`, `(KeyError, ValueError)` | Added `Timeout` and `ConnectionError`, ordered from specific to general with `RequestException` last |

The function name, return values and the `__main__` block are unchanged.

## Results

**Live run:** the endpoint in the assignment is hypothetical. The request
failed with an SSL hostname mismatch
(`certificate is not valid for 'api.text-processing.com'`). The script caught
it in the `ConnectionError` block and printed one `Connection failed: ...`
message to `sys.stderr`, with no traceback. Certificate verification was not
disabled.

**Simulated run:** to test the rest of the function, `requests.post` was
replaced with a mock that returns `{'label': 'pos'}`:

```bash
python3 -c "
from unittest.mock import patch, MagicMock
import sentiment_analyzer_refactored as s
r = MagicMock(); r.json.return_value = {'label': 'pos'}
with patch('requests.post', return_value=r):
    print(s.analyze_sentiment('I love this course'))
"
```

Output: `positive`. This output is simulated and does not come from a real API
server.

## Verification Against Best Practices

- The API key is read from the environment, is not hardcoded and is never
  printed.
- A missing key is handled before any request is sent.
- The header format is `Authorization: Bearer <key>`.
- A timeout is set, so `Timeout` can actually occur.
- `Timeout` and `ConnectionError` have their own `except` blocks with distinct
  messages.
- The `except` blocks are ordered from specific to general.

## Limitations

- The timeout value is hardcoded.
- There are no retries for temporary network failures.
- Authentication failures (401 or 403) are not separated from other HTTP
  errors.
- The success case was verified with a mock, which does not check the request
  headers.
